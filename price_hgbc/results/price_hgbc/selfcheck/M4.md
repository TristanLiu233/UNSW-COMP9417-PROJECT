## 5. Task 4: comparisons (reported only; the main choice is unchanged)

| Scheme | q99 | μ₀ | σ₀ | Truncated days | h chosen | ARL₀ at chosen h (5–95 %) | Alarms on real 2014 |
|---|---|---|---|---|---|---|---|
| **main: log loss, truncated** | 1.0494 | 0.4435 | 0.1988 | 4 | **6** | 912.5 (456–3650) | 1 (2014-09-26) |
| misclassification, truncated | 0.5625 | 0.2083 | 0.1351 | 3 | 6 | 730.0 (406–1825) | 1 (2014-12-25) |
| log loss, no truncation | — | 0.4459 | 0.2080 | 0 | 6 | 730.0 (406–1825) | not run (comparison only) |

* **Misclassification:** it picks the same h with a lower ARL₀ that only just meets the target (730 = target). It is
  coarser (steps of 1/48), and it is optimistic in 2014 (next point).
* **Why 2014 misclassification is optimistic and log loss less so:** P1 tuned τ on the two 2013 folds, but the whole
  configuration including τ = 0.45 was then selected by 2014 BalAcc among many candidates. So the 2014
  misclassification rate is partly in-sample for the threshold choice, μ₀ is too low, and future false alarms become
  more likely. Log loss uses no threshold. It inherits only the milder optimism of choosing the feature set and
  leaves on 2014, so its 2014 level is a less biased reference.
* **Truncation:** without it, μ₀ and σ₀ grow (σ₀ 0.2080 vs 0.1988). At h = 6, ARL₀ falls from 912.5 to 730: single
  extreme days push S over h more often. At h = 5 the order reverses (182.5 vs 146), because the smaller σ₀ of the
  truncated scheme makes ordinary days count more. Truncation mainly stops one bad day (e.g. 2014-08-02, log loss 1.53)
  from contributing more than (q99 − μ₀)/σ₀ − k = 2.55 to S.

## 8. Decision for you: `ref_update` A or B

Option B demonstration (`m4/ref_update_B_demo_2013.csv`): REF's configuration fitted on 2010-01-29 … 2012-12-31
and evaluated out of sample on 2013 gives q99 = 0.876, μ₀ = 0.450, σ₀ = 0.149. The 2014 reference (option A) is
q99 = 1.049, μ₀ = 0.443, σ₀ = 0.199. Similar means, but a 25 % smaller σ₀ under B.

| | A: keep the 2014 μ₀, σ₀, q99 | B: re-estimate after each retrain |
|---|---|---|
| Pros | simple; no extra fit; the h ↔ ARL₀ calibration stays exactly as validated; easy to explain | the reference follows the new model and market (e.g. a structurally higher error level after 2020 does not trigger alarms forever); consistent with "what is normal for this model" |
| Cons | after a regime change the old reference may be too low (repeated alarms that use up the 6-retrain budget) or too high (missed drift); the new model's error level is unknown | needs an inner fit and 12 months of held-out data per retrain (more compute, shorter effective training window for that fit); h = 6 was calibrated for the 2014 σ₀ and is **not** re-validated for new references, so ARL₀ can drift; a small σ₀ (as in the 2013 demo) makes the detector more sensitive |

**Decision (user, 2026-11-11): option A.** After every retrain the detector keeps q99 = 1.0494, μ₀ = 0.4435, σ₀ = 0.1988 and h = 6, and S is reset to 0. Recorded in `cusum_config.json` (`ref_update = "A"`, `ref_update_decision`). Option B stays implemented but unused. Its main risk under A, a reference that no longer fits after a regime change, remains listed in §10.

Applying the decision changed only `ref_update`, `ref_update_decision` and the `m4.py` code hash in the config. All M4 CSVs are byte-identical. `test_config_hashes` now expects `ref_update = "A"`, and `validate_config` rejects any value other than null, A or B. Fast suite after the change: 125 passed.

## 10. Remaining risks

* **ARL₀ rests on one year (2014).** The bootstrap only resamples 51 weeks, so the 5–95 % band (456–3650 days) shows
  how uncertain the calibration is; h = 6 is on a steep part of the curve.
* **Reference level is an approximation.** The frozen Stage 2 model will be refit on 2010–2014, so it has no
  out-of-sample 2014 error. Using REF's 2014 out-of-sample errors (model trained to 2013) as its normal level is an approximation.
* **Seasonality and weekday effects** (Monday mean 0.30 vs ~0.48 on other weekdays, lag-7 ACF 0.22) can cause false
  alarms or delay real ones, e.g. a run of high-error weeks in one season.
* The 2014 series itself raises one alarm (WARN), consistent with ARL₀ ≈ 900 days but a reminder that alarms are not
  proof of drift.
* The misclassification comparison is optimistic in 2014 (§5); the main scheme avoids τ but not all selection optimism.
* No git repository, so the code version is identified by file hashes only.
