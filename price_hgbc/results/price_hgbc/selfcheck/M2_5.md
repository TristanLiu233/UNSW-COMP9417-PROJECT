## Step 2: P1 feature code

* **`src/common/features.py` does not exist**, and **`train_four.py` is not a file on any branch.**
  On `baseline`, guide §D (`ablation/消融说明.md` l. 206) tells the reader to create `train_four.py` by pasting the
  A1/A2/B1/B2 column lists and a code block from the document. A recipe cannot be imported without copying it.
* **What is imported instead (unchanged):** the importable P1 package that produced the group's results:
  `comp9417_project_kit/ablation/features.py` (`load_study`, `build_features`, `CORE`) and `ablation/models.py`
  (`predict_raw`). Branch `baseline`, commit **`116e2966310232894c71d9f7b73bc468a09eeee2`**. All four files used
  (`features.py`, `models.py`, `消融说明.md`, `results/selection.csv`) were last changed in that commit and are clean vs HEAD.
  Imports run with `dont_write_bytecode`, so no `__pycache__` lands in the kit.
* The saved model needs the fitted estimator, but `predict_raw` only returns probabilities. So the estimator's
  parameters are **captured from the object P1's `predict_raw` builds**, not retyped. A plain
  `HistGradientBoostingClassifier` with those parameters is refit and must equal `predict_raw`'s output bit for bit
  (asserted in `run()` and in `test_saved_model_equals_p1_predict_raw`).
