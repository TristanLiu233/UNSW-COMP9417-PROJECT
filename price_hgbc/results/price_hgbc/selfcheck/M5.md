## Task 2: day-by-day interface `predict_price(model, tau, history, weather_next)` (`src/price_hgbc/m5.py`)

P1's code has no day-by-day API. P1 itself uses `_construct` for its own as-of replays (`validate_study`), so the adapter calls
the same function. It is imported from the kit, not copied:
* keep the last 35 days of `history`;
* append the 48 D+1 rows with weather only and NaN market columns;
* call P1 `_construct` with P1's day-type model (fitted once on ≤ 2013 profiles);
* return the CORE columns in the model's `feature_names_in_` order.

Output: `p_up` and `nsw_price_up`, indexed by `weather_next.index`. No fixed calendar slices are used, so year boundaries need no special handling.
