## 2. 公共规则（对应 M6 的 1–7）

1. **标签闸门：** 第 d 天的标签只在第 d 天结束后放出。截止日 D 的训练只能读取 ≤ D 的标签；CUSUM 在第 d 天的预测保存之后才读取 d 的标签。
2. **重训时序：** 在第 D 天结束时重训，新模型从 D+1 起生效，绝不预测 D 或更早的日子。
3. **重训内容：** 一次重训重新拟合整个 pipeline，包括标准化器，并重新选 τ。这些合起来算 1 次重训。C、class_weight 和 recipe 不变，从 `selected_price_model.json` 读取（与 P4 `fit_final` 相同）。
4. **重训的实现（S1、S2、S3 共用同一种 τ 选法）：**
   * **S1、S3（扩展窗口）：** 直接调用 P4 的 `logistic_price.final_training.fit_final(data, D)`，使用默认参数（不传 `validation_folds`、`thresholds`、`fixed_threshold`）。传入的 `data` 先截断到 D+1 天 00:00，`fit_final` 自己也会截断。这样 Stage 2 的重训和 Stage 3 的最终训练是同一份代码。
   * **S2（滑动窗口）：** 新写 `src/price_lr/fit_sliding.py::fit_sliding(data, D, start)`，逐行沿用 `fit_final` 的逻辑，唯一区别是训练目标只取 `start ≤ 日 ≤ D` 的行（调参模型取 `start ≤ 日 < 验证期起点`）。特征仍由完整前缀 2010-01-01 … D+1 00:00 计算，以保证滞后特征有足够历史。
   * **`fit_final` 的默认 τ 选法（即两者共同的规则）：** 验证期 = [D − 1 个日历年 + 1 天, D]（`pd.DateOffset(years=1)`）；调参模型用训练窗口内验证期之前的所有日子，以固定的 C 和权重拟合，对验证期做样本外预测；阈值网格 0.25–0.60、步长 0.01（36 个）；选 BalAcc 最高的；平局时选离 0.5 最近的，再平局取较小值。τ 固定后重新初始化，用整个训练窗口拟合最终 scaler 和模型，从 D+1 起使用。运行时 `threadpool_limits(1)`，`ConvergenceWarning` 视为错误。
   * **等价性测试：** `fit_sliding(data, D, start=2010-01-29)` 必须与 `fit_final(data, D)` 在系数、截距、scaler 均值和方差、τ 以及对任意 3 天的预测上逐位一致。不一致就停下来报告，不运行 S2。
5. **训练窗口：** S1、S3 用扩展窗口（2010-01-29 … D）；S2 用滑动窗口，`start = D − 3 个日历年 + 1 天`（2016 年那次是 2014-01-01 … 2016-12-31，共 1,096 天；其中调参模型用 2014-01-01 … 2015-12-31，验证期 2016-01-01 … 2016-12-31）。更早的日子可以用来算滞后特征，但不作为训练目标。
6. **记录：** 每次拟合都记录截止日、生效日、训练行数、调参模型的行数、选中的 τ、验证期 BalAcc 和耗时。
7. **模型编号：** S0 以及各策略第一次重训之前用 `LR_frozen`；之后用 `<S>_r<n>_<cutoff>`。

## 3. CUSUM 标定（照搬 M4，只换参考误差）

* **参考预测：** LR 用 2010-01-29 … 2013-12-31 拟合（68,784 行），对 2014 年做样本外预测，即 P4 `validation_predictions.csv.gz` 的 `log_interactions31_probability` 列。运行时再重新拟合一次核对，两者逐档完全一致才使用。**不读取 2015-01-01 00:00 之后的任何数据。**
* **日误差 e_D（主方案）：** 当日 48 档的平均 log loss，概率裁剪到 [1e-6, 1 − 1e-6]。
* **对照方案（只做报告，不用于任何选择）：** τ₀ = 0.42 时的日错分率；以及不截断的版本。
* **截断：** q99 = 2014 年 e_D 的 99% 分位数（`numpy.quantile`，线性插值，365 个日值），之后 e_D ← min(e_D, q99)。
* **参考统计量：** μ₀ 和 σ₀ 取截断后 2014 年 e_D 的均值和样本标准差（ddof = 1）。
* **统计量：** z_D = (min(e_D, q99) − μ₀)/σ₀，S_D = max(0, S_{D−1} + z_D − k)，k = 0.5。S_D > h 时报警；`update` 返回清零之前的 S_D，然后把内部状态清零。
* **选 h：** 在 {3, 4, 5, 6, 7, 8, 10} 中取 ARL₀ ≥ 730 天的最小值；如果都达不到，就暂取 10，并标出来交给我决定。
* **ARL₀ 的估计：** 按周分块 bootstrap。块是 2014 年内完整的周一到周日，共 51 周（2014-01-06 … 2014-12-28）。每次重复抽 522 周，按抽到的顺序拼接，取前 3,650 天。共 1,000 次，用 `default_rng(0)` 生成一个共用的周索引矩阵（1000 × 522），所有 h 和所有误差方案都用它。每次重复的 ARL₀ = 3650 / 报警次数，没有报警记为 +∞。报告中位数和 5%、95% 分位数。
* **检测延迟材料（只针对选中的 h，不用于选择）：** 漂移幅度 δ ∈ {0.5, 1, 2, 3} σ₀；两种噪声模型（iid N(0,1)，以及真实 2014 z 的分周 bootstrap），各 1,000 次，seed 0，上限 3,650 天。
* **参考期在重训后不变：** 采用方案 A，μ₀、σ₀、q99 永不更新。
* **2014 年内的报警：** 只作为标定记录，不能据此修改 h。2015-01-01 时 S 从 0 开始。

## 4. 策略

* **S0：** 冻结 LR（直接加载 P4 的工件，不重新拟合），所有天都用它，不重训。每一档的预测类别和概率都必须与 P4 `replay_predictions.csv.gz` 的 `log_interactions31` 和 `log_interactions31_probability` 列完全一致，共 207,456 档。
* **S1：** 扩展窗口，在 2016、2018、2020、2022、2024 年末重训，下一年 1 月 1 日生效，共 5 次。
* **S2：** 重训日期同 S1，用三年滑动窗口，共 5 次。
* **S3：** CUSUM 触发，方案 A。每天 d 依次：
  1. 用当前生效的模型预测；
  2. 保存预测；
  3. 放出 d 的标签，计算 d 的平均 log loss；
  4. 用全精度配置值执行 `Cusum.update`；每个报警日都把 S 清零，包括被抑制的报警；
  5. 如果报警：满足以下两个条件才重训，否则记录抑制原因（先判断 `cooldown`，再判断 `budget`）：
     * 这是第一次重训，或者距离上一次**实际重训**的报警日 ≥ 180 天；
     * 已有重训次数少于 6；
  6. 重训就是 `fit_final(data, d)`（扩展窗口，和 S1 相同），截止日为 d，从 d+1 起生效。
* **预算：** 每个“模型 × 策略”在 2015-01 至 2026-10 之间最多重训 6 次；初始训练不计入。程序里加断言保证。

## 11. Stage 3 决策规则（写于任何 LR S1–S3 成绩之前）

本节决定提交包里电价模型用哪种策略训练。只比较 LR 的 S0–S3；HGBC 的 S0–S3 只作为"其他模型"的对照，不参与本规则。

1. **主要依据：** 2015-01-01 … 2024-12-31 全部 3,653 天的 BalAcc（官方 `da`，与第 5 节相同）。按它从高到低给 S0–S3 排名，第一名记为 F。
2. **差异不显著时：** 候选集 C = {F} ∪ {X：第 5 节配对 bootstrap 中 F − X 的 95% 区间包含 0}。在 C 内依次比较：
   1. 2015–2024 内实际生效的重训次数更少的优先；
   2. 次数相同时，扩展窗口（S1、S3）优先于滑动窗口（S2）；
   3. 仍然相同时，取 2015–2024 BalAcc 更高的。

   这样得到的是**暂定选择** P。紧接在 P 之后的**备选** R，取 2015–2024 BalAcc 排名中除 P 以外最高的那个。P 和 R 在 11-17 写入 `stage3_provisional.json`，写入时不含任何 2025–2026 的数字。
3. **检测器触发策略不是必选：** spec 要求比较检测器触发的策略，没有要求最终使用它。S3 是否被选中，只由第 1–2 条决定。
4. **2025–2026 只用来否决（11-18 上午第一次打开）：**
   * 计算 S0–S3、b1、b7 在 2025-01-01 … 2026-10-31（669 天）上的 Acc 和 BalAcc。S3 在这两年的报警和重训照常按因果顺序进行，预算从 2015-01 起累计。
   * 如果 P 在这段时间的 BalAcc 低于 b1，而 R 不低于 b1，就改用 R；其他任何情况都保留 P，包括 P 和 R 都低于 b1，或者 R 在这两年更高但 P 不低于 b1。
   * 所有策略在 2025–2026 的成绩都完整报告，报告里写明哪一条规则起了作用。
5. **最终模型（截止日 2026-10-31）：**
   * P 是 S1 或 S3（扩展窗口）：最终模型 = P4 `fit_final(data, 2026-10-31)`。先重跑核对，τ 必须等于 P4 记录的 0.49，最终训练行数必须是 293,760；不一致就停下来报告。
   * P 是 S2（滑动窗口）：最终模型 = `fit_sliding(data, 2026-10-31, start=2023-11-01)`，即最近三个日历年，验证期 2025-11-01 … 2026-10-31。
   * P 是 S0：最终模型 = `fit_final(data, 2026-10-31)`。理由：spec 的 Stage 3 要求用截至 10-31 的发布数据训练最终模型；S0 只表示 Stage 2 里不重训，不表示提交 2014 年的模型。（待确认，见下方第 7 条）
   * 不管选中哪个，live 周模型都冻结；S3 的 CUSUM 状态不带进 package，`predict` 内部不训练。
6. **记录：** 决策过程写进 `results/price_lr/stage3/decision.md`，包括 P、R、第 2 条每一步的比较值、第 4 条的判断，以及最终工件的 SHA-256 和 `training.json`。
7. **本节的待确认项：**
   * 第 2 条的合并顺序：重训次数 → 窗口类型 → BalAcc；
   * 第 4 条的否决条件："P 低于 b1 且 R 不低于 b1"；
   * 第 5 条中 S0 被选中时的处理。

## 12. Live 周 G 的历史类比（只用于报告 §5，不用于选策略）

1. **目标：** 估计 G = BA_m − BA_b1（单位：百分点）。b1 是"昨天同一半小时"基线（官方 `da.baseline`）。live 周是 2026-12-07 … 12-13，部署模型截止于 2026-10-31，模型年龄 37–43 天。
2. **主方案（与 P3 的需求类比同口径）：**
   * 对 Y = 2015 … 2024，用最终训练方法、截止日 Y-10-31 训练一个模型，预测 Y-12-07 … Y-12-13 共 7 天、336 档；
   * 计算 BA_m、BA_b1、G，以及 Acc 和两类样本数；
   * 两种训练方法今天都算好：扩展窗口 `fit_final(data, Y-10-31)`；滑动窗口 `fit_sliding(data, Y-10-31, start=(Y−3)-11-01)`。11-18 按第 11 节选中哪种就用哪种；P 是 S0 时用扩展窗口。
3. **预测方式：** 批量计算特征后逐档预测。每年抽 1 天，用 P4 的逐日接口 `build_features_for_day` 复算，要求逐位一致。
4. **汇总：** n = 10。报告中位数、中间 80%（`numpy.quantile` 的 0.1 和 0.9，线性插值）、最小值、最大值和 G > 0 的周数；同一张表也给出 BA_b1 本身。Y = 2025 那一周在 11-18 打开 2025–2026 之后补上，n 变为 11，补上前后的结果分开记录。
5. **补充（只做描述）：** 按 P4 `live_week_framework.md` 的规则，从 S1、S2、S3 的 `models_log` 中取每个实际部署模型在训练截止后第 37–43 天的窗口。只纳入 7 天都在 2015–2024 内、且这 7 天里该模型一直在部署的窗口，不用后来重训的模型回填。`LR_frozen` 的窗口就是 P4 已有的 2015-02-06 … 02-12。
6. **局限（写进交接说明）：**
   * 12-07 … 12-13 在其他年份不一定是周一到周日；
   * 只有 10 个样本，且年份之间不独立；
   * 历史类比用的是再分析天气，live 周的天气输入可能不同；
   * 第 2 条的模型虽然沿用最终训练方法，但不是提交的那个模型。

   这里得到的分布是描述性的历史类比，不是预测区间，也不是 live 成绩。
7. **本节的待确认项：** 第 2 条的年份范围和第 4 条的统计量。
